# The C library symbols that the code in the Linux libraries may use
#
# verify_libc_imports (build-linux-common.sh) fails the build if code linked into
# libarchive.so, other than musl's libc.a and the compiler's libgcc.a, uses a symbol of
# libc.a that this list does not name. The list holds what the x64, arm64 and arm libraries
# use; an entry that only one of them uses says so.
#
# Why each needs checking: libarchive.so contains musl, and its code is compiled against
# musl's headers. In a glibc process, though, its calls of these functions go to glibc's,
# which come first when the dynamic loader binds them, so glibc's code then reads and writes
# what musl's headers laid out. Where the two lay a type out differently, glibc's function
# reads or writes the wrong bytes. glibc's pthread_mutex_init, for one, clears 48 bytes on
# arm64, where musl's mutex is 40: linux-pthread-init.c initialises mutexes and condition
# variables in its place. A name that musl's headers rename on arm, to the function with a
# 64-bit time_t, binds to glibc's only where glibc has one of that name, and otherwise runs
# musl's own.
#
# Before adding a symbol, compare what musl's headers and glibc's (for its default symbol
# version) say that it reads and writes, on x64, arm64 and arm, and note any difference here.
# The entries marked MISMATCH differ on arm (32-bit), where glibc's default functions use a
# 32-bit off_t and 32-bit file system types and musl's are 64-bit. libarchive used them
# before this list was made; they are not resolved yet.
#
# One symbol per line; "#" starts a comment.
